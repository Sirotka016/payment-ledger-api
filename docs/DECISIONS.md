# Decisions

В этом файле будут фиксироваться важные технические решения по проекту.

## Sanic app factory и dev-запуск

Приложение создается через `create_app()`, чтобы его было удобно использовать в тестах и дальше расширять через routes,
настройки и зависимости.

При ручном запуске через PyCharm Sanic падал в `dev=True`, потому что dev-reloader ожидает приложение на уровне модуля,
а не только внутри блока `if __name__ == "__main__"`.

Решение: оставить фабрику `create_app()`, но дополнительно создать глобальный объект приложения:

```python
app = create_app()
```

Для тестов используется отдельное имя приложения, чтобы не конфликтовать с основным Sanic app:

```python
app = create_app("payment-ledger-api-test")
```

## TYPE_CHECKING для связей между моделями

В моделях SQLAlchemy есть связи между `User`, `Account` и `Payment`. Эти классы ссылаются друг на друга, поэтому прямые
импорты внутри каждого файла могут привести к циклическим импортам.

Для таких импортов используется `TYPE_CHECKING`: линтер и PyCharm видят нужные типы, но во время запуска приложения эти
импорты не выполняются.

Такой вариант оставляет связи моделей читаемыми и не усложняет структуру проекта.

## Alembic и стартовые данные

Для миграций используется Alembic, потому что структура базы должна быть версионирована и воспроизводима при локальном запуске и в Docker.

Первую миграцию пишу вручную: схема небольшая, а тестовое задание требует сразу создать пользователя, его счет и администратора.

Пароли стартовых аккаунтов сохраняются в виде PBKDF2-хешей, а не открытым текстом. Сами тестовые email/password будут указаны в README ближе к финальной инструкции по запуску.
